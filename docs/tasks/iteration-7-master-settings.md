# ТЗ: итерация 7 — мастер сам настраивает страницу

Цель: владелец страницы (её по-прежнему заводит оператор: `beauty seed-demo`, `beauty master
assign-owner`) без оператора ведёт свою страницу в кабинете: профиль, услуги, рабочие часы,
выходные даты, правила записи, фото работ и аватар, публикация. Решения владельца:
регистрация страниц — только оператором; экраны — в стиле текущих макетов кабинета
(`@beauty/ui`), без отдельных макетов.

Вне итерации: самостоятельная регистрация страниц, смена адреса страницы (slug), порядок
услуг перетаскиванием, обработка фото (кадрирование, уменьшение), разовый перерыв в дне.

## 1. Контракт (группа `master`)

| Метод | Что |
|---|---|
| `GET /me/settings` | `MasterSettings`: страница (`MasterPage`) + статус, рабочие часы, выходные даты, все правила записи |
| `PUT /me/profile` | имя, падежи имени, специализация, адрес, «о себе», часовой пояс |
| `POST /me/services`, `PUT /me/services/{id}`, `DELETE /me/services/{id}` | услуги (удаление — в архив, история записей остаётся) |
| `PUT /me/working-hours` | рабочие часы по дням недели (несколько интервалов — перерывы) |
| `PUT /me/days-off` | выходные даты (прошедшие отбрасываются) |
| `PUT /me/booking-rules` | срок подтверждения, срок переноса, минимум до визита, горизонт, шаг сетки |
| `POST /me/photos` (multipart), `DELETE /me/photos/{id}` | фото работ (jpeg/png/webp до 8 МБ, до 30 штук) |
| `PUT /me/avatar` (multipart), `DELETE /me/avatar` | аватар |
| `POST /me/publish`, `POST /me/unpublish` | открыть или скрыть страницу |

Все изменения возвращают `MasterSettings` — экран обновляется одним ответом. Ошибки — problem+json:
422 (`invalid_profile`, `invalid_schedule`, `invalid_booking_rules`, `invalid_service`,
`invalid_photo`), 409 `master_not_publishable` (нет услуг или рабочих часов; последняя услуга
или пустой график у опубликованной страницы), 413 `photo_too_large`, 404 `service_not_found`.

## 2. Бэкенд

* Tenancy: `GetMasterSettings`; команды уже есть (профиль, услуги, расписание, правила,
  выходные, фото, публикация) — нужен API кабинета и коды ошибок.
* Фото хранятся в файловом хранилище (`photos/…`) и раздаются публично без подписи:
  `GET /api/v1/media/public/photos/<key>` (только префикс `photos/`; голосовые остаются по
  подписанным ссылкам). Ссылка фото — путь `/api/v1/media/public/…` (в контракте
  `uri-reference`): страница мастера открывается на его поддомене, API — на том же origin.
* Изменения страницы видны агенту сразу (инструкции хода читают страницу на каждом ходе).

## 3. Фронтенд (PWA мастера)

* «Настройки» — хаб: карточка статуса страницы (черновик / опубликована, «Открыть
  страницу», «Опубликовать» с причиной, если нельзя), разделы: Профиль, Услуги, График и
  выходные, Правила записи, Фото работ, Уведомления (как было).
* Экраны разделов — формы с сохранением, ошибками сервера у полей и тостами; оффлайн —
  сохранение недоступно.
* Гейтвей `MasterSettingsGateway` (HTTP + MSW-моки для разработки и e2e).

## 4. Качество

* Бэкенд: интеграционные тесты API (контракт по схемам, права только владельца, ошибки,
  публикация, фото: загрузка, публичная раздача, удаление).
* Фронтенд: unit-тесты форм (валидация расписания, цены в тенге ↔ тиынах), e2e: правка
  профиля, добавление услуги, график, публикация; скриншоты экранов.

## 5. Итоги (2026-10-16)

* Бэкенд: `GET /me/settings` и все правки отвечают `MasterSettings`; фото и аватар — в
  файловом хранилище, публичная раздача `/api/v1/media/public/photos/…` с вечным кэшем,
  при удалении и замене файл удаляется. Интеграционные тесты: права только владельца,
  ошибки (`invalid_schedule`, `invalid_booking_rules`, `invalid_photo`, …), публикация и
  её препятствия (`publish_blockers`).
* Фронтенд: хаб «Настройки» (статус страницы, «Открыть страницу», «Скрыть» с
  подтверждением, «Опубликовать» с причинами) и разделы Профиль (с фото профиля), Услуги
  (нижний лист, цена в тенге ↔ тиыны), График и выходные (несколько интервалов в дне,
  проверка пересечений до отправки), Правила записи, Фото работ (несколько файлов подряд,
  проверка формата и размера до загрузки). Офлайн — сохранение недоступно.
* Моки повторяют проверки сервера и влияют на остальные экраны (выходные и часы — на окна
  и график, скрытая страница — 404 у клиента).
* Живая проверка в браузере через nginx на реальном API (вход — сценарий Telegram):
  аватар, профиль, услуга, перерыв, выходная дата, правила, фото работы, скрыть и открыть.
  Публичная страница сразу показывает изменения; в выходную дату окон нет; шаг сетки
  15 минут виден в окнах; скрытая страница — 404, после публикации — 200.
