# ТЗ: итерация 8 — расшифровка голосовых

Цель: голосовые клиентов и голосовые поручения мастера превращаются в текст. Клиент и
мастер видят расшифровку под голосовым, ИИ-администратор отвечает по ней, а не передаёт
каждое голосовое мастеру. Контракт не меняется: поле `transcript` у голосового было с
итерации 1, обновление приходит кадром `message.updated`.

Вне итерации: голосовые ответы мастера клиенту (в диалоге мастер пишет текстом),
расшифровка старых голосовых, выбор языка в интерфейсе.

## 1. Решения

1. **Распознавание — OpenRouter** (`POST /api/v1/audio/transcriptions`): тот же ключ, что у
   агента; модель по умолчанию `openai/whisper-large-v3` (русский и казахский, язык
   определяется сам); `zdr` — только провайдеры без хранения данных. Записи браузеров
   (`webm`, `m4a`, `ogg`) уходят как есть, без перекодирования.
2. **Сменный адаптер** `SpeechToText`: `openrouter`, `fake` (любая запись — фраза из
   настроек: разработка, стенд без ключа), `off`. Общая часть — `VoiceTranscriber`: файл из
   хранилища → сервис → текст; любая неудача — `None` и запись в журнал, не исключение.
3. **Расшифровка — в фоне, после сохранения.** Голосовое появляется в ленте сразу; worker
   (очереди `conversations.voice` и `agent.office_voice`, без общей транзакции на время
   внешнего вызова) расшифровывает и обновляет сообщение.
4. **Агент отвечает по итогу расшифровки.** Conversations публикует
   `conversations.voice.transcribed` (текст или `null`); ресепшн делает ход по нему.
   Голосовое поручение мастера: `agent.office.voice_transcribed` → ход кабинета. Не
   получилось — как раньше: голосовое клиента уходит мастеру, мастеру в кабинете —
   «повторите или напишите текстом».

## 2. Настройки

`BEAUTY_SPEECH__PROVIDER` (`off` | `openrouter` | `fake`), `BEAUTY_SPEECH__MODEL`,
`BEAUTY_SPEECH__API_KEY` (пусто — `BEAUTY_AGENT__PROVIDER_API_KEY`), `BEAUTY_SPEECH__ZDR`,
`BEAUTY_SPEECH__LANGUAGE` (пусто — автоопределение), `BEAUTY_SPEECH__FAKE_TEXT`.

## 3. Качество

* Unit: запрос к OpenRouter (base64, формат, `zdr`, язык) и отказы; `VoiceTranscriber`
  (выключено, нет файла, отказ, тишина, неизвестный формат); маршрутизация событий агента;
  расшифровка поручения в домене (обновление ленты, повтор — no-op).
* Интеграционные: голосовое клиента → текст в истории, кадр `message.updated`, в диалоге
  мастера, ход агента с текстом; неудача → ход без текста; голосовое поручение → текст в
  ленте кабинета и ровно один ход после расшифровки.

## 4. Итоги (2026-10-19)

* Живой прогон на стенде (Hermes, сценарная модель, сценарный распознаватель): голосовое
  клиента → «Хочу записаться на массаж спины завтра» под голосовым → агент через MCP создал
  заявку и ответил; от отправки голосового до ответа ≈ 1 с. Голосовое поручение →
  расшифровка в ленте кабинета → ход кабинета.
* Стенд нашёл ошибку развёртывания: у `worker` не было тома с файлами (голосовые лежали
  только у `api`). Том `files` подключён и к `worker`.
* В диалоге мастера «расшифровываем…» показывается только первые 2 минуты: если текста так
  и нет (распознавание выключено или не удалось), подпись не висит вечно.
* Запросы к настоящему OpenRouter проверены unit-тестами по документации; качество на
  русском и казахском нужно проверить на рабочем стенде с ключом (модель меняется
  настройкой, запасной вариант — `openai/gpt-4o-transcribe`).
