# ТЗ: итерация 11 — рассылки объявлений

Цель: мастер сообщает всем своим клиентам новость — новая услуга, акция, отпуск, перенос
приёма — сам или поручением ИИ-администратору, с фото. Отписки нет (решение владельца).

## 1. Рассылка

* Получатели — все клиенты мастера (у кого есть переписка), на момент отправки.
* Содержимое: текст (1–1000 символов) и одно фото по желанию (JPEG, PNG, WebP до 8 МБ).
* Жизненный цикл: черновик → отправляется → отправлена. Черновик можно править, добавить или
  убрать фото, удалить. Отправленную не отменить.
* Лимит: одна рассылка за 24 часа (по началу отправки). Хозяин сервиса может запретить
  рассылки мастеру в админ-панели.
* Доставка — в фоне порциями: объявление приходит в чат каждого клиента отдельным видом
  сообщения («Объявление» с фото) и push-уведомлением. Повторная доставка не дублирует
  сообщение (ключ — рассылка и переписка). Объявление не забирает диалог у агента.
* Агент ресепшна знает о недавних объявлениях (за 30 дней) — отвечает на «а скидка ещё
  действует?».

## 2. Кабинет

* «Клиенты» → «Рассылка»: текст, фото, «Получат N клиентов», отправка с подтверждением;
  история рассылок (дата, текст, доставлено). Пока действует лимит — когда можно следующую.
* Поручение: «Разошли всем: с 1 ноября массаж лица, −20% первую неделю» — агент рассылает
  сразу (`send_broadcast`, см. «Доработка») и кладёт в ленту карточку рассылки с ходом
  доставки. Черновик — если мастер просит черновик или хочет фото (`prepare_broadcast`):
  карточка с «Добавить фото», «Отправить N клиентам», «Удалить».

## 3. Админ-панель

* Карточка мастера: «Рассылки» — разрешены (переключатель, в журнал действий) и последние
  рассылки (дата, текст, получателей, доставлено).

## 4. Бэкенд

* Conversations: агрегат `Broadcast`, вид сообщения `announcement`; доставка — консьюмер
  события начала рассылки; фото — в хранилище файлов, ссылки подписанные.
* Agent: инструмент кабинета `prepare_broadcast`, вид сообщения ленты поручений
  `broadcast`; объявления — в инструкциях ресепшна.
* Notifications: push клиенту об объявлении.
* API кабинета: `GET/POST /me/broadcasts`, `GET/PUT/DELETE /me/broadcasts/{id}`,
  `PUT/DELETE /me/broadcasts/{id}/photo`, `POST /me/broadcasts/{id}/send`.
  Админ: `PUT /admin/masters/{id}/broadcasts`.

## 5. Качество

* Unit: жизненный цикл, лимит, запрет, доставка без дублей; карточка поручения.
* Интеграционные: черновик → фото → отправка → объявление у всех клиентов, push; лимит 24 ч
  (429); запрет из админки (403); черновик агента через MCP кабинета.
* Фронт: unit, e2e (рассылка с фото из кабинета; карточка в поручениях; объявление у
  клиента), скриншоты.

## Итоги (2026-10-20)

Сделано по ТЗ; проверено вживую на docker-стенде: черновик → фото → «Отправить» →
доставлено 8 из 8 клиентам за ~1 с; у клиента в чате «Объявление от Алисы» с фото (ссылка
подписанная, файл отдаётся); вторая рассылка в те же сутки — 429 `broadcast_cooldown`;
агент ресепшна видит объявление в инструкциях («Недавние объявления мастера…»).

* Conversations: агрегат `Broadcast`, вид сообщения `announcement`; доставка — порциями
  по 50 переписок, курсор и ключ `uuid5(рассылка, переписка)` — повтор без дублей;
  запрет — отдельная таблица (миграция 0012). Объявление не забирает диалог у агента.
* Агент кабинета: `prepare_broadcast` — черновик и карточка в ленте поручений; отправляет
  только мастер кнопкой.
* Push: клиенту — об объявлении, мастеру — о готовом черновике.
* Админ-панель: «Рассылки» в карточке мастера — запрет/разрешение (в журнал) и последние.

Тесты: бэкенд — домен рассылки, карточка агента, интеграционные (фото, порции, лимит,
запрет, черновик агента через MCP, переключатель админки); фронт — модель, гейтвей на
моках, e2e (рассылка с фото, черновик агента, объявление у клиента, запрет в админке).

Не проверено вживую: черновик по поручению на настоящей модели (сценарная модель стенда
`prepare_broadcast` не вызывает; путь покрыт интеграционным тестом с настоящим MCP).

## Доработка (2026-10-20): «мастер сказал — агент сделал»

Владелец: через поручения рассылку создать не получалось. Причины: инструкция запрещала
агенту отправлять самому, а Hermes держал старый список MCP-инструментов в кэше профиля.

* Кабинет: `send_broadcast(text)` — черновик и сразу отправка всем клиентам; карточка в
  ленте показывает ход доставки. Лимит 24 ч или запрет — агент говорит мастеру причину,
  черновик остаётся в ленте, мастер отправит его кнопкой позже. `prepare_broadcast` —
  только когда мастер просит черновик или хочет приложить фото.
* `beauty agent bootstrap` и подключение мастера сбрасывают кэш схем MCP-инструментов
  профилей (`cache/mcp_schema_cache.json`); после bootstrap — `docker compose restart
  hermes`.

Тесты: unit (сразу, отказ по лимиту — черновик в ленте; сброс кэша), интеграционный через
настоящий MCP (вторая за сутки — черновик агента), моки и e2e («Разошли всем…» → «Рассылка ·
Отправлено N клиентам»; черновик с фото → отправка кнопкой).
