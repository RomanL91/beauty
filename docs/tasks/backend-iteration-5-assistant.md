# ТЗ: бэкенд, итерация 5 — поручения мастера ИИ-администратору («кабинет»)

Цель: мастер даёт поручения своему ИИ-администратору текстом (экран «Поручения» PWA мастера,
группа контракта `assistant`): «что у меня завтра?», «закрой воскресенье», «отмени Дарью и
предложи ей пятницу», «подтверди все заявки на завтра». Агент выполняет их инструментами,
а если нужно решение мастера — спрашивает карточкой с вариантами (`choice`). После итерации
PWA мастера целиком работает на реальном API.

Вне итерации: расшифровка голосовых (голосовое поручение агент просит повторить текстом),
многошаговые задачи с ожиданием клиента (`task_progress`, «если Оксана не ответит до 18:00»),
разовый перерыв в дне («обед на 14:00»), память о клиенте между визитами.

## 0. Решения

1. **Отдельный профиль Hermes для кабинета.** Runs API не умеет ограничивать инструменты
   на запуск, поэтому у мастера два профиля: ресепшн (`m-<id>`) и кабинет (`m-<id>-office`),
   у каждого свой ключ Runs API, свой MCP-токен и свой MCP-эндпоинт: `/mcp` — инструменты
   ресепшна, `/office/mcp` — инструменты мастера. Клиентский агент не видит инструментов
   мастера вовсе; роль в тикете — второй рубеж.
2. **Ресепшн без памяти и поиска по сессиям** (исправление итерации 4): `memory` и
   `session_search` профиля общие для всех клиентов мастера — это канал утечки данных одного
   клиента другому. Контекст диалога держит сессия Hermes (`session_id` = переписка).
   Памяти кабинета (предпочтения мастера) это не касается: там только мастер.
3. **Лента поручений — в контексте agent** (`agent.office_messages`): это рабочий канал
   мастера с его администратором, а не переписка с клиентом. Сообщения — в форме
   контракта `Message` (`text`, `voice`, `choice`, `system`); в поток `/me/events` —
   `message.created|updated` с `conversation_id = null`.
4. **Выбор мастера — новый ход.** Инструмент `ask_master` создаёт карточку `choice`;
   ответ мастера (`POST /me/assistant/choices/{id}`) отмечает вариант и запускает ход
   «Мастер выбрал: …» в той же сессии кабинета (сессия Hermes — на день мастера).
   Если ход задал вопрос, его итоговый текст в ленту не идёт: ответом служит карточка.
5. **Ничего необратимого без ясности.** Отмена записи, запись клиента, выходной на день с
   записями — только если поручение однозначно; иначе `ask_master`.

## 1. Инструменты кабинета (MCP `/office/mcp`)

| Инструмент | Что делает |
|---|---|
| `day_schedule(date)` | записи, заявки и свободные окна дня (как график кабинета) |
| `find_free_slots(service_id, date?)` | окна услуги |
| `find_clients(query)` | клиенты мастера по имени или цифрам телефона |
| `book_client(client_id, service_id, start)` | записать клиента от имени мастера (сразу подтверждено) |
| `confirm_request(appointment_id)` / `decline_request(appointment_id, offer_alternatives)` | решения по заявкам |
| `cancel_appointment(appointment_id, reason?)` | мастер отменяет запись; клиенту — сообщение и другие окна |
| `set_day_off(date, off)` | закрыть или открыть дату |
| `message_client(client_id, text)` | написать клиенту от имени администратора |
| `ask_master(question, options[], detail?)` | карточка выбора мастеру |

## 2. Соседние контексты

* Booking: `Appointment.cancel_by_master` (причина `master_cancelled`), команда
  `CancelAppointmentByMaster`. Conversations: клиенту — «… отменила запись …» и другие окна.
* Tenancy: `ChangeDayOff(master_id, day, off)` — одна дата, атомарно.
* Conversations: `PostOnMasterBehalf(master_id, client_id, text)` — сообщение агента
  клиенту по поручению мастера (диалог создаётся при необходимости, «нужны вы» не трогается).

## 3. API (контракт не меняется)

* `GET /me/assistant/messages?before&limit`, `POST /me/assistant/messages` (текст или
  голосовое multipart; повтор по `client_id` — то же сообщение).
* `POST /me/assistant/choices/{choice_id}` `{option_id}` → карточка с выбором; другой
  вариант уже выбран — 409 `choice_already_answered`; нет такого — 404.
* `/me/events`: сообщения ленты поручений.

## 4. Провижининг

* Шаблон `beauty-office-template` (MCP `${BEAUTY_OFFICE_MCP_URL}`, память включена, SOUL
  кабинета). `beauty agent provision <slug>` идемпотентно добавляет профиль кабинета мастерам,
  у которых есть только ресепшн; `beauty agent bootstrap` приводит к шаблонам оба вида.

## 5. Качество

* Unit: лента и выбор, тикеты кабинета, инструменты, обработчик хода.
* Интеграционные: MCP кабинета по HTTP (чужая роль, токен ресепшна не пускает в кабинет),
  поручения через API, выбор → новый ход, отмена мастером доходит до клиента.
* Живой прогон с Hermes и сценарной «моделью»: «что у меня завтра?», «закрой воскресенье»
  с подтверждением выбором.
