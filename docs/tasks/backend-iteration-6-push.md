# ТЗ: бэкенд, итерация 6 — push-уведомления и напоминание о визите

Цель: клиент и мастер узнают о важном, даже когда PWA закрыто. Фронтенд готов с
итерации 1 (группа `push`: плашка подписки, `POST/DELETE /push/subscriptions`, service
worker показывает `PushPayload` и по нажатию открывает `url`). Бэкенд хранит подписки,
решает, кому и что отправить, шифрует и отправляет Web Push; напоминает клиенту о визите.

Вне итерации: настройки уведомлений (что присылать), тихие часы, e-mail/SMS/Telegram.

## 0. Решения

1. **Новый контекст `notifications`.** Подписки и отправка — отдельная ответственность;
   триггеры — события соседних контекстов (Booking, Conversations, Agent).
2. **Подписка принадлежит учётной записи и приложению.** `app=client` — клиент на странице
   мастера `master_slug` (у каждого поддомена свой service worker и свой endpoint);
   `app=master` — владелец кабинета (мастер по токену, иначе 403 `not_a_master`). Повтор
   того же `endpoint` — та же подписка (ключи и владелец обновляются).
3. **Web Push без тяжёлых зависимостей:** шифрование RFC 8291 (`http-ece`), VAPID RFC 8292
   (`py-vapid`), отправка — наш `httpx`. Ответ 404/410 — подписка удаляется. Без ключей
   VAPID отправка выключена (в журнал).
4. **Что отправляем.**

   | Событие | Кому | kind | url |
   |---|---|---|---|
   | новая заявка | мастеру | `appointment_requested` | `/schedule/<дата>` |
   | клиент отменил запись | мастеру | `appointment_declined` | `/schedule/<дата>` |
   | клиент пишет в диалог, который ведёт мастер | мастеру | `message` | `/chats/<id>` |
   | агент передал вопрос мастеру | мастеру | `message` | `/chats/<id>` |
   | агент ответил на поручение | мастеру | `task_done` | `/assistant` |
   | заявка подтверждена | клиенту | `appointment_confirmed` | `/chat` |
   | заявка отклонена / истекла / мастер отменил | клиенту | `appointment_declined` | `/chat` |
   | ответ агента или мастера | клиенту | `message` | `/chat` |
   | напоминание о визите | клиенту | `reminder` | `/chat` |

   `tag` — по переписке или записи: новое уведомление заменяет старое того же разговора.
5. **Напоминание — таймер Booking.** При подтверждении записи: за 24 ч до визита, а если
   до визита меньше суток — за 2 ч (если и это уже прошло — не напоминаем). Запись получает
   отметку `reminder: sent`, событие `booking.appointment.reminder_due`; Conversations пишет
   в чат «Напоминаем: …», Notifications — push клиенту.
6. **Conversations сообщает о каждом новом сообщении** событием `conversations.message.added`
   (автор, вид, превью, кто ведёт диалог) — Notifications решает, будить ли кого-то.

## 1. API (контракт не меняется)

* `POST /push/subscriptions` (`PushSubscriptionInput`) → 201 `{id}`; 401; 403 для
  `app=master` без кабинета; 422 — нет `master_slug` у клиента или мастер не найден.
* `DELETE /push/subscriptions/{id}` → 204; чужая или нет — 404.

## 2. Настройки

`BEAUTY_PUSH__VAPID_PUBLIC_KEY`, `BEAUTY_PUSH__VAPID_PRIVATE_KEY`, `BEAUTY_PUSH__SUBJECT`
(`mailto:…`). Публичный ключ — и в сборку фронта (`VITE_VAPID_PUBLIC_KEY`).
Ключи создаёт `beauty push keys`.

## 3. Качество

* Unit: шифрование (расшифровка закрытым ключом подписки), VAPID-заголовок, тексты
  уведомлений, правило напоминания.
* Интеграционные: подписка (повтор, чужое удаление, мастер без кабинета), уведомления по
  событиям через обработчик со «записывающим» отправителем, 410 удаляет подписку,
  напоминание задачей планировщика → сообщение в чате и push.

## 4. Итоги (2026-10-17)

* Сквозная проверка отправителя против настоящего Mozilla autopush (как Firefox): «браузер»
  зарегистрировался по протоколу push, `WebPushSender` отправил уведомление с подписью VAPID,
  autopush доставил его в сокет, расшифровка дала ровно `PushPayload`.
* Интеграционные тесты: уведомления по событиям — через обработчик со «записывающим»
  отправителем; напоминание — задачей планировщика (сообщение в чате, `reminder: sent`, push).
* Системные строки и карточки заявок в чате push не дублируют: о записи сообщают события
  Booking, о переписке — только ответы агента и мастера.
* Push работает только в безопасном контексте (https или `*.localhost`): со стенда через
  `nip.io` по http браузер подписку не даст.
