# ТЗ: итерация 10 — «Клиенты» в кабинете мастера

Цель: у мастера есть своя клиентская база — кто к нему ходит, когда был и когда придёт,
как к нему обращаться и что о нём важно помнить. Заметки ведут и мастер, и ИИ-администратор;
агент учитывает их в разговоре с клиентом.

Вне итерации: теги и сегменты, дни рождения, экспорт, полный телефон клиента (мастер, как и
раньше, видит маску `…89 67` — номер раскрывает только Telegram-переписка).

## 1. Клиент мастера

* Клиент мастера — тот, у кого есть переписка с мастером (одна на пару «мастер, клиент»).
* **Имя у мастера.** Сейчас все клиенты — «Новый клиент · …89 67». Мастер (или агент по
  поручению) задаёт имя — «Айгерим»; пустое имя возвращает подпись по телефону. Имя видно
  в чатах, в графике (открытые заявки и записи, новые заявки) и в инструкциях агента — агент
  обращается к клиенту по нему. До 60 символов.
* **Заметки.** Короткие факты о клиенте: «аллергия на лаванду», «любит без музыки»,
  «приходит с дочкой». Автор — мастер или ИИ-администратор; до 500 символов, до 100 заметок
  на клиента. Мастер удаляет любую заметку; агент только добавляет. Повтор того же текста
  не создаёт новую заметку.

## 2. Кабинет: раздел «Клиенты»

* **Список**: имя, телефон (маска), визитов, последний визит, ближайшая запись, число
  заметок. Поиск по имени или цифрам телефона; фильтр «все / с записью впереди»; свежие
  по последней активности сверху; подгрузка страницами.
* **Карточка** (`/clients/:id`): имя (изменить), телефон, с нами с, визитов, отмен; ближайшие
  записи; история визитов (дата, услуга, цена, статус); заметки (добавить, удалить; у заметок
  агента — пометка «ИИ»); кнопка «Написать» → переписка.
* Из переписки «Карточка клиента» ведёт в карточку раздела.

## 3. ИИ-администратор

* **Ресепшн**: в инструкциях хода — заметки о текущем клиенте (служебные: клиенту их не
  цитирует, но учитывает). Инструмент `remember_client(note)` — сохранить устойчивый факт,
  который клиент сам сообщил о себе (предпочтения, противопоказания, как обращаться); не
  записи и не разовые договорённости.
* **Кабинет**: `client_card(client_id)` — карточка (имя, визиты, ближайшие записи, заметки);
  `add_client_note(client_id, text)`; `rename_client(client_id, name)`. Поручения вида «запиши,
  что Айгерим аллергик на лаванду», «клиент …89 67 — это Айгерим».

## 4. Бэкенд

* Новый контекст `clientbook`: агрегат `ClientFile` (мастер, клиент, имя, заметки).
  Событие `ClientRenamed` → Conversations (подпись клиента в переписке) и Booking (открытые
  заявки и записи; новые заявки берут имя у Clientbook).
* Список и карточка — read-модель поверх переписок (Conversations), записей (Booking) и
  карточек (Clientbook), только чтение.
* API кабинета: `GET /me/clients`, `GET /me/clients/{id}`, `PUT /me/clients/{id}/name`,
  `POST /me/clients/{id}/notes`, `DELETE /me/clients/{id}/notes/{note_id}`.

## 5. Качество

* Unit: имя и заметки (длины, дубли, лимит, удаление), переименование → событие; инструкции
  с заметками; инструменты агента.
* Интеграционные: список и карточка по контракту, поиск, фильтр; переименование доходит до
  чата и графика; заметка агента через MCP; чужой клиент — 404.
* Фронт: unit, e2e (список → карточка → имя → заметка), скриншоты.

## Итоги (2026-10-20)

Сделано по ТЗ; проверено вживую на docker-стенде (браузер → nginx → API → PostgreSQL):
клиент написал мастеру → появился в «Клиентах» как «Новый клиент · …80 71» → мастер дал имя
«Сауле» и заметку «Аллергия на лаванду» → имя в списке чатов, в инструкциях ресепшна —
«Клиент: Сауле» и заметка (служебно).

* Контекст `clientbook` (миграция 0011): карточка — имя и заметки; список и карточка —
  read-модель поверх переписок, записей и карточек.
* Имя: событие `ClientRenamed` → подпись в переписке и в открытых записях; новые заявки
  подписаны именем из картотеки.
* Агент: ресепшн видит заметки о клиенте и сохраняет новые (`remember_client`); кабинет —
  `client_card`, `add_client_note`, `rename_client`.
* Кабинет: «Клиенты» (поиск, «С записью», «Показать ещё»), карточка (имя, визиты, отмены,
  впереди, история, заметки с пометкой «ИИ»), переход из переписки.

Тесты: бэкенд +10 (домен, инструменты агента, имя в заявках, интеграционные: список,
карточка, переименование до чата и графика, заметка агента через MCP); фронт: тест
гейтвея на моках, e2e «Клиенты».

Ограничения: подпись клиента в уже прошедших записях остаётся прежней (снимок на момент
заявки); имя у мастера видит агент — подписи вроде «сложная клиентка» лучше писать в заметки.
