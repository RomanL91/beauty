# ТЗ: итерация 9 — админ-панель хозяина сервиса

Цель: хозяин сервиса без терминала заводит и ведёт мастеров, видит, как работает сервис
(записи, клиенты, ИИ-администратор, очереди), блокирует нарушителей и управляет
доступом других администраторов. Панель — отдельное приложение `admin.<домен>`.

Вне итерации: просмотр переписок клиентов (персональные данные — только с согласия
мастера), биллинг и тарифы, рассылки, подключение агента мастеру из панели (нужен доступ
к Docker — остаётся командой `beauty agent provision`, панель её подсказывает).

## 1. Вход: логин и пароль

* Администраторы — свои учётные записи (не клиенты и не мастера): логин, имя, пароль.
  Пароль — scrypt с солью; минимум 10 символов.
* Первый администратор — командой на сервере: `beauty admin create <логин>` (пароль
  спрашивается или читается из stdin). Остальных заводят в панели.
* Сессия — на сервере (можно отозвать): httpOnly-cookie `bk_admin` (путь
  `/api/v1/admin`, `SameSite=Strict`, `Secure` в продакшене), срок 12 ч. Изменяющие
  запросы несут заголовок `X-CSRF-Token` (выдаётся при входе и в `GET /admin/auth/me`).
* Перебор: 5 неверных паролей подряд — учётная запись заблокирована на 15 минут. Ответ
  на неверный логин и на неверный пароль одинаковый.
* Отключённый администратор теряет все сессии; себя отключить нельзя.

## 2. Разделы

| Раздел | Что |
|---|---|
| Сводка | мастера (всего, опубликовано, с агентом), клиенты, записи впереди, переписки; за 30 дней по дням: заявки, подтверждения, отмены, новые клиенты, сообщения, ходы агента и сбои |
| Мастера | список с поиском и фильтром статуса; создать мастера (адрес, имя и падежи, специализация, пояс, телефон владельца); карточка: страница, владелец (сменить), опубликовать/скрыть, агент (включить/выключить; не подключён — команда подключения), статистика за 30 дней, ближайшие записи |
| Клиенты | поиск по телефону; у кого записывались, записи, последний вход; заблокировать (с причиной) / разблокировать |
| ИИ-администратор | модель и распознавание речи; ходы по дням (ресепшн/кабинет, успешные/сбои, среднее и p95 время), передачи мастеру, последние сбои; голосовые: расшифровано/нет |
| Администраторы | список, добавить, отключить/включить, задать пароль; сменить свой пароль |
| Журнал | все изменения из панели: кто, что, над чем, когда |
| Система | база, очередь событий (не отправлено, возраст старейшего), отложенные задачи (просрочено), включены ли агент, распознавание, push |

## 3. Бэкенд

* Контекст `admin`: администраторы, сессии, журнал действий; отчёты — read-модель поверх
  схем других контекстов (только чтение). Изменения — командами контекстов-владельцев:
  Tenancy (регистрация, владелец, публикация), Agent (включить/выключить), Identity
  (блокировка).
* Identity: блокировка учётной записи клиента — отзыв всех сессий, вход и обновление
  сессии запрещены (`account_blocked`, 403).
* Agent: журнал ходов (`agent.runs`: роль, мастер, итог, длительность) — для раздела
  агента и сводки.

## 4. Фронтенд

`apps/admin`: React, `@beauty/ui`, desktop-first (боковое меню), на телефоне — нижнее
меню. Гейтвей `AdminGateway`, MSW-моки группы `admin`, unit- и e2e-тесты, скриншоты.
nginx: `admin.*` → приложение панели.

## 5. Качество

* Unit: пароли (хеш, проверка, длина), блокировка перебора, сессия и CSRF, права.
* Интеграционные: вход/выход/me, CSRF, перебор, отключённый админ; сводка и отчёты по
  контракту; создание мастера и смена владельца → кабинет открывается новому телефону;
  публикация; блокировка клиента → вход и refresh запрещены; журнал действий.
